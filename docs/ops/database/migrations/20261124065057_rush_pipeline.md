Adds the recruitment pipeline's chapter-private tables (stages, tags, notes and ratings) and `rush_candidates.closed_reason`, and purges a member's ratings on account deletion (#5924).

## Promotion

- **Purpose**: five new tables (`rush_stages`, `rush_tags`, `rush_candidate_tags`, `rush_candidate_notes`, `rush_candidate_ratings`), each with RLS on and no policies, read only by the API's service-role client. Composite foreign keys on `(id, chapter_id)` keep a tag, note or rating inside its candidate's chapter, which needs a new unique constraint `rush_candidates_id_chapter`. `rush_candidates` gains a nullable `closed_reason`. `anonymize_user` is redefined in full with one added delete of the member's ratings. No stages are backfilled: the API writes a chapter's defaults on its first read.
- **Checks**: `select count(*) from rush_stages;` returns 0 right after the push, and rises as chapters open the pipeline. `select count(*) from rush_candidates where closed_reason is not null;` returns 0. `select prosrc like '%delete from rush_candidate_ratings%' from pg_proc where proname = 'anonymize_user';` returns true.
- **Promoter notes**: push before the API that reads it. Until then the new pipeline, stage, tag, note and rating routes 500. The existing candidate routes and the chat card are unaffected, except that the API now writes `closed_reason`, so that API must not run ahead of this migration. Writes no data.

## Rollback

Worth reverting only if the tables themselves cause trouble. Revert the API routes first, because they read every table here. Forward migration:

Redefine `anonymize_user` first, in the same migration and before the drops: the current definition deletes from `rush_candidate_ratings`, so dropping the table first breaks every account deletion. Copy the current definition from this migration and take out its ratings delete (the playbook's rule: the current definition, not an older file's).

```sql
-- 1. create or replace function anonymize_user(...) : this migration's body, minus the
--    `delete from rush_candidate_ratings` line
-- 2. then:
drop table if exists public.rush_candidate_ratings;
drop table if exists public.rush_candidate_notes;
drop table if exists public.rush_candidate_tags;
drop table if exists public.rush_tags;
drop table if exists public.rush_stages;
alter table public.rush_candidates drop column if exists closed_reason;
alter table public.rush_candidates drop constraint if exists rush_candidates_id_chapter;
```
