Adds chat timeouts (#6006): three nullable columns on `members` (`chat_timeout_until`, `chat_timeout_reason`, `chat_timeout_by`), a partial index for the API's sweep, and the new `members:timeout` permission for every tier and role that already manages channels.

## Promotion

- **Purpose**: An officer can stop a member ranked below them from posting or reacting in the chapter's channels for a set time (`spec/behavior/chat/README.md` § Timeouts). After it:
  - a member row may carry a timeout (until when, an optional reason up to 200 characters, and who set it); a reason never stands without a time (`members_chat_timeout_reason_needs_until`);
  - every `role_tiers` row holding `channels:manage` also holds `members:timeout`, and every role holding `channels:manage` outside that (and not `*`) has `members:timeout` switched on as an override, as `20261113040007_chapter_groups.sql` did for `groups:manage`.
- **Checks**:
  - `select count(*) from role_tiers where 'channels:manage' = any (permissions) and not ('members:timeout' = any (permissions));` returns 0.
  - `select count(*) from roles where 'channels:manage' = any (permissions) and not ('members:timeout' = any (permissions)) and not ('*' = any (permissions)) and not (permission_overrides ? 'members:timeout');` returns 0.
  - `select count(*) from members where chat_timeout_until is not null;` returns 0 until an officer times someone out.
- **Promoter notes**: Writes data only in the permission backfill (one array append per officer tier, one override per qualifying role). Either deploy order is safe: the API before #6006 reads none of the columns and ignores the unknown permission, and the API from #6006 needs the columns, so this goes first, as Deploy production does.

## Rollback

Worth it only together with reverting the API from #6006. A forward migration ([playbook](../../db-rollback-playbook.md#decision-matrix)) that drops the columns, which ends every running timeout, and takes the permission back off. A chapter that switched `members:timeout` on or off by hand since loses that choice.

```sql
update public.role_tiers
   set permissions = array_remove(permissions, 'members:timeout');
update public.roles
   set permission_overrides = permission_overrides - 'members:timeout'
 where permission_overrides ? 'members:timeout';
drop index if exists public.members_chat_timeout_until;
alter table public.members
  drop constraint if exists members_chat_timeout_reason_needs_until,
  drop constraint if exists members_chat_timeout_reason_len,
  drop column if exists chat_timeout_by,
  drop column if exists chat_timeout_reason,
  drop column if exists chat_timeout_until;
```
